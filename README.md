# DATAM

Интернет-магазин одежды с личным кабинетом и админкой. Фронтенд написан на React и Vite, API — на FastAPI, данные хранятся в PostgreSQL. Весь проект запускается через Docker Compose.

| Сервис | Адрес |
| --- | --- |
| Магазин | [localhost](http://localhost) |
| Админка | [localhost/admin](http://localhost/admin) |
| pgAdmin | [localhost/pgadmin](http://localhost/pgadmin) |
| Документация API | [localhost/docs](http://localhost/docs) (только при `DEBUG=true`) |

## Быстрый запуск

Нужны Docker Compose и `make`.

```bash
cp .env.example .env
```

В `.env` задайте свои значения для `SECRET_KEY`, `POSTGRES_PASSWORD` и `PGADMIN_DEFAULT_PASSWORD`. Для ключа и пароля PostgreSQL подойдут длинные случайные hex-строки: `openssl rand -hex 32`. Пароль PostgreSQL должен быть безопасным для URL, поскольку Compose вставляет его в `DATABASE_URL`.

При `DEBUG=false` (продакшн) backend не запустится, если `SECRET_KEY` короче 32 символов или оставлен по умолчанию, а документация API (`/docs`, `/openapi.json`) отключена.

```bash
make up
make seed
```

`make up` собирает и запускает контейнеры; миграции применяются при старте backend. `make seed` добавляет демо-каталог из `backend/data/catalog.json` в текущую базу `datam`. Команда идемпотентна: повторный запуск не создаёт дубликаты, а у существующих товаров только обновляет теги стиля и цвета. Автоматического seed при запуске нет.

## ИИ-стилист

Кнопка «ИИ-стилист» справа внизу магазина открывает боковой чат. Покупатель описывает повод, погоду и дресс-код, задаёт бюджет и уточняет подборку в диалоге. Товары можно открыть или добавить в корзину по одному, явно выбрав размер. На телефоне панель занимает экран. В админке, при входе и оформлении заказа кнопка скрыта.

Подбор доступен после входа; после авторизации покупатель возвращается к открытой панели. Диалог хранится только в памяти вкладки, сохраняется при закрытии панели и переходах по магазину, очищается при смене аккаунта, перезагрузке или по кнопке «Новый диалог». API принимает до восьми предыдущих сообщений по 1000 символов. Отмена прекращает ожидание в браузере; модель на сервере может закончить уже начатую генерацию.

Подбор делает локальная модель в [Ollama](https://ollama.com), запущенной на компьютере, а не в Docker:

```bash
ollama pull qwen3.5:2b   # один раз, около 2,7 ГБ
ollama serve             # если Ollama не запущена как приложение
```

Модель выбирает вещи из каталога, который ей передаёт backend. Backend проверяет товары, категории и бюджет. Для строгого повода вещи со стилем «повседневный» в подбор не попадают; стиль товара задаётся в админке. Если модель вышла за рамки, её один раз просят исправиться. Для подбора используется самый доступный размер в наличии, выбранный покупателем размер может стоить дороже. Модель и общий таймаут подбора задаются через `OLLAMA_MODEL` и `OLLAMA_TIMEOUT_SECONDS` (не более 120 секунд). На один процесс backend выполняется один подбор; при занятости или недоступности Ollama API отвечает `503`, а чат предлагает повторить запрос.

## Доступ к админке

На новой базе сначала зарегистрируйте пользователя в магазине. Затем откройте pgAdmin и выполните в Query Tool для базы `datam`:

```sql
UPDATE users SET role = 'admin' WHERE email = 'you@example.com';
```

Подставьте email зарегистрированного пользователя и войдите под ним на [localhost/admin](http://localhost/admin). В админке доступны товары, категории, пользователи и заказы. Заказы можно искать, фильтровать, менять их статус и редактировать данные доставки до отправки. Отмена до отправки возвращает товары на склад.

Для входа в pgAdmin используйте `PGADMIN_DEFAULT_EMAIL` и `PGADMIN_DEFAULT_PASSWORD` из `.env`. Сервер DATAM уже добавлен; при подключении к нему введите `POSTGRES_PASSWORD`.

## Команды

| Команда | Что делает |
| --- | --- |
| `make up` | Собирает и запускает проект |
| `make down` | Останавливает контейнеры, сохраняя данные |
| `make restart` | Перезапускает сервисы |
| `make ps` | Показывает состояние контейнеров |
| `make logs` | Открывает логи |
| `make shell` | Открывает shell в backend |
| `make migrate` | Применяет миграции вручную |
| `make seed` | Добавляет демо-каталог в текущую базу |
| `make test` | Запускает тесты backend в контейнере на отдельной базе `datam_test` |
| `make lint` | Проверяет стиль backend через ruff (нужен установленный `ruff`) |
| `make format` | Форматирует backend через ruff |
| `make lint-frontend` | Проверяет фронтенд: ESLint и сборку с проверкой типов |
| `make build` | Пересобирает образы |
| `make clean` | Удаляет локальные кеши Python и инструментов |
| `make reset` | Удаляет контейнеры и **все тома проекта**, включая базу данных |

Полный список: `make help`.

## Как устроен проект

| Путь | Содержимое |
| --- | --- |
| `frontend/src/app` | Маршруты и настройка приложения |
| `frontend/src/pages/admin` | Страницы админки |
| `frontend/src/features/admin` | Запросы и типы админского API |
| `frontend/src/entities` | Модели и API товаров, заказов, пользователей и других сущностей |
| `backend/app/routes` | Публичные и админские HTTP-маршруты |
| `backend/app/services` | Логика каталога, заказов и аккаунтов |
| `backend/database/migrations` | Миграции Alembic |
| `backend/seed.py`, `backend/data/catalog.json` | Загрузка демо-каталога и сами данные |
| `.github/workflows/ci.yml` | CI: ruff, тесты backend, ESLint и сборка фронтенда на каждый PR |

Админские маршруты API: `/api/admin/catalog/products`, `/api/admin/catalog/categories`, `/api/admin/users` и `/api/admin/orders`. Страницы фронтенда используют адреса `/admin/...`.

## Данные и сеть

PostgreSQL работает в отдельной базе `datam`. Данные базы сохраняются в томе `postgres-data`, настройки pgAdmin — в `pgadmin-data`, загруженные файлы — в `backend-data`. Порты PostgreSQL и backend не опубликованы наружу; Nginx на `127.0.0.1:80` передаёт `/api` и `/media` в backend, а `/pgadmin` — в pgAdmin.
